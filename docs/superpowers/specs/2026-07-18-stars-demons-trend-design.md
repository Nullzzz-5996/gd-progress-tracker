# График динамики звёзд и демонов

**Дата:** 2026-07-18
**Статус:** утверждён

## Задача

На вкладке «Статистика» показать, как менялись звёзды и демоны со временем.

Возможность была заложена предыдущей работой ([2026-07-18-account-stats-design.md](2026-07-18-account-stats-design.md)):
снимки счётчиков аккаунта уже копятся в таблице `AccountStatsSnapshots`, новая строка пишется
только при изменении хотя бы одной из девяти метрик. Рисовать график тогда сознательно отложили.

## Ограничение, которое надо принять

Сейв-файл Geometry Dash хранит только текущие значения счётчиков — истории в нём нет,
и восстановить её задним числом невозможно. На момент написания в базе **один снимок**
(18.07.2026, 886 звёзд, 17 демонов). График наполняется по мере игры: новая точка появляется
тогда, когда пользователь наберёт звёзды или пройдёт демона, и приложение это заметит.

Это свойство данных, а не дефект реализации.

## Решения

**Одна диаграмма с двумя осями Y.** Звёзд 886, демонов 17 — разница в 52 раза, на общей оси
демоны выродились бы в прямую по нулю. Звёзды идут по левой оси, демоны по правой
(`ScalesYAt = 1`). Это позволяет видеть связь: скачок демонов рядом со скачком звёзд.

**Рисуем всегда, даже при одном замере.** Решение пользователя. Одна точка на графике вместо
объясняющего текста. При нуле снимков график пустой — без падения и без сообщения.

## Реализация

**Данные.** `IAccountStatsRepository` получает `GetHistoryAsync(CancellationToken ct = default)` —
все снимки по возрастанию `CapturedAt`, затем `Id` (тот же порядок, что уже используется в
`GetLatestAsync`, только по возрастанию). Ограничения по количеству нет: строки пишутся
только при изменении метрик, их физически мало.

**Вью-модель.** `StatsViewModel` получает три свойства: `TrendSeries` (`ISeries[]`),
`TrendXAxes` и `TrendYAxes` (`Axis[]`).

- Звёзды — `LineSeries<double>`, подпись «Звёзды», цвет `#FFD54F` (тот же, что у карточки звёзд).
- Демоны — `LineSeries<double>` с `ScalesYAt = 1`, подпись «Демоны», цвет `#EF5350`
  (тот же, что у карточки демонов). Совпадение цветов связывает кривую с карточкой.
- Ось X — позиционные метки из `CapturedAt` в формате `дд.ММ`. Это тот же приём, что уже
  применён в трёх существующих графиках страницы (`Axis.Labels` позиционно к `Values`),
  никакой новой техники в проект не вводится.
- Ось Y — два элемента: левая для звёзд, правая для демонов (`Position = AxisPosition.End`).

**Момент построения.** История загружается в конце `LoadAccountAsync` на **обеих** ветках —
и когда сейв реально прочитан, и когда чтение пропущено по неизменившемуся времени файла.
Иначе после появления нового снимка график показывал бы вчерашние данные.

**Разметка.** Один `CartesianChart` в `StatsPage.xaml` под девятью карточками аккаунта,
до подзаголовка «Прогресс в трекере». Заголовок секции — «Динамика звёзд и демонов».
Высота 260, как у соседних диаграмм.

## Крайние случаи

| Ситуация | Поведение |
|---|---|
| Ноль снимков (сейв не найден) | Пустой график, без исключения |
| Один снимок | График с одной точкой |
| Много снимков | Две кривые по своим осям |
| Ошибка чтения истории из БД | Ловится существующим `try/catch` в `LoadAccountAsync`, сообщение уходит в `AccountStatus`, карточки остаются |

## Тестирование

- `AccountStatsRepositoryTests`: `GetHistoryAsync` возвращает снимки по возрастанию времени;
  на пустой таблице — пустой список.
- `StatsViewModelTests`: две серии построены, значения совпадают со снимками, у серии демонов
  `ScalesYAt = 1`, меток оси X столько же, сколько точек; один снимок даёт одну точку;
  ноль снимков не роняет загрузку.
