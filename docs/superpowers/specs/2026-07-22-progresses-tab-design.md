# Вкладка «Прогрессы»

**Дата:** 2026-07-22
**Статус:** утверждён

## Задача

Новая вкладка «Прогрессы» с таблицей ручного учёта прогресса по уровню в личном
формате пользователя: 4 столбца, до 100 строк на уровень. Переход на вкладку — по
кнопке «Добавить прогресс», которая появляется при выборе уровня на вкладке «Уровни».

Это **отдельные данные**, не связанные с существующими `ProgressRecord`. Старая форма
«Добавить прогресс» в панели деталей уровня остаётся как есть (её кнопка переименуется,
см. ниже), новая функциональность живёт рядом.

## Столбцы таблицы

Одна строка = один заход/запись. Столбцы:

1. **Практика — за сколько попыток** (`PracticeAttempts`), пример: `23`. Вручную.
2. **С парта до парта** (`SegmentRange`), пример: `24-35`. Вручную.
3. **До ста** (`ToHundredRange`), пример: `67-100`. Вручную.
4. **С нуля** (`FromZero`), пример: `0-97`. **Автоматически**, не хранится:
   вычисляется на лету как `0–{Level.BestNormalPercent}` — лучший результат «с нуля»
   в обычном режиме, уже отслеживаемый для уровня (столбец Norm% на вкладке «Уровни»).
   Значение «живое»: одинаково во всех строках уровня и обновляется вместе с лучшим %
   (например после импорта из игры). Read-only.

Столбцы 1–3 хранятся как строки: примеры — свободные числа/диапазоны, жёсткой валидации
нет, пользователь печатает как удобно. Ввод обрезается по краям (trim), пустая ячейка → `null`.

## Пользовательский поток

1. На вкладке «Уровни» пользователь выбирает уровень — открывается панель деталей.
2. В шапке панели деталей появляется кнопка **«Добавить прогресс»**.
3. Нажатие переносит на вкладку «Прогрессы», уже открытую на этом уровне.
4. На вкладке «Прогрессы»: сверху выбор уровня (можно переключиться на любой другой),
   ниже таблица из 4 столбцов и кнопка «Добавить строку».
5. Пользователь добавляет строки (до 100) и заполняет столбцы 1–3; правки сохраняются
   сразу. Столбец 4 показывается автоматически.

## Устройство

### Модель (Core)

Новая сущность `LevelProgressRow`:

- `Id : int` — первичный ключ.
- `LevelId : int` + nav `Level? Level` — уровень.
- `Order : int` — позиция строки в таблице уровня (1…100).
- `PracticeAttempts : string?` — столбец 1.
- `SegmentRange : string?` — столбец 2.
- `ToHundredRange : string?` — столбец 3.
- `CreatedAt : DateTime`.

Столбец 4 в модели отсутствует — он производный от `Level.BestNormalPercent`.
`Level` получает навигационную коллекцию `List<LevelProgressRow>` для каскадного удаления.

### Данные (Data)

- Конфигурация в `AppDbContext`: связь с `Level`, каскадное удаление вместе с уровнем
  (как у `ProgressRecord`), строковые столбцы с разумным `MaxLength`.
- Новая миграция EF (таблица `LevelProgressRows`).
- Репозиторий `ILevelProgressRowRepository` (абстракция в Core, реализация в Data):
  - `Task<IReadOnlyList<LevelProgressRow>> GetByLevelAsync(int levelId, ct)` — по `Order`.
  - `Task<LevelProgressRow> AddAsync(LevelProgressRow row, ct)`.
  - `Task UpdateAsync(LevelProgressRow row, ct)`.
  - `Task DeleteAsync(int id, ct)`.

  Репозиторий не пересчитывает агрегаты уровня (эти данные на них не влияют) — в отличие
  от `IProgressRepository`.

### ViewModels

- `ProgressesViewModel` (вью-модель страницы):
  - `Levels` — список уровней для переключателя, `SelectedLevel`.
  - `Rows : ObservableCollection<LevelProgressRowViewModel>` — строки выбранного уровня.
  - `FromZeroDisplay` — вычисляемое `0–{SelectedLevel.BestNormalPercent}` (столбец 4).
  - `AddRowCommand` — добавляет строку; заблокирована при 100 строках (`CanAddRow`).
  - `DeleteRowCommand`.
  - `LoadAsync()` — грузит уровни, выбирает целевой (из контекста навигации) или первый,
    грузит его строки. Смена `SelectedLevel` перегружает строки.
- `LevelProgressRowViewModel` — обёртка строки: редактируемые `PracticeAttempts`,
  `SegmentRange`, `ToHundredRange` (правка → сохранение через страницу-VM), read-only
  `FromZero` (берёт из родительской VM).
- `IAppNavigator` (абстракция в ViewModels, реализация в App поверх `INavigationService`):
  `void OpenProgresses(int levelId)`.
- `IProgressNavigationContext` (singleton, ViewModels): `int? TargetLevelId { get; set; }` —
  как `IAppNavigator` передаёт странице, какой уровень открыть (VM транзитная и читает
  контекст в `LoadAsync`). Реализация `IAppNavigator` выставляет контекст и вызывает навигацию.

Сохранение правок: при изменении столбца 1–3 в строке-VM вызывается
`ProgressesViewModel`, который зовёт `UpdateAsync` для этой строки. Добавление/удаление
строк — через репозиторий с последующей перенумерацией `Order`.

### App (UI)

- `Views/ProgressesPage` (+ VM в конструкторе, `LoadAsync` на `Loaded` — как `StatsPage`):
  сверху `ComboBox` выбора уровня; ниже `DataGrid` из 4 столбцов (1–3 редактируемые,
  4-й — read-only, привязан к `FromZeroDisplay`); кнопка «Добавить строку»
  (выключается на 100). Разметка на `DynamicResource` под темы.
- `MainWindow.xaml`: пункт `NavigationViewItem` **«Прогрессы»** (после «Уровни»),
  `TargetPageType="{x:Type views:ProgressesPage}"`.
- `App.xaml.cs`: регистрация `ProgressesPage`, `ProgressesViewModel` (transient),
  `ILevelProgressRowRepository` (singleton), `IProgressNavigationContext` (singleton),
  `IAppNavigator` (singleton).
- `DashboardPage.xaml`: в шапке панели деталей — кнопка **«Добавить прогресс»**, видимая
  при выбранном уровне, привязана к новой команде `LevelsViewModel.OpenProgressesCommand`,
  которая зовёт `IAppNavigator.OpenProgresses(SelectedRow.Level.Id)`.
  `LevelsViewModel` получает `IAppNavigator` в конструктор.
- Разрешение конфликта кнопок: у **существующей** формы «Добавить прогресс» в панели
  деталей кнопку переименовать в **«Добавить запись»** (сама форма и логика без изменений),
  чтобы не было двух одинаковых кнопок.

## Тестирование

По образцу существующих тестов:

- Репозиторий: добавление/чтение по уровню в порядке `Order`; обновление; удаление;
  каскадное удаление строк вместе с уровнем.
- `ProgressesViewModel`: `AddRowCommand` добавляет строку и заблокирована на 100;
  смена `SelectedLevel` грузит его строки; `FromZeroDisplay` = `0–BestNormalPercent`;
  правка столбца сохраняется через репозиторий; удаление строки перенумеровывает `Order`.
- Навигация: `OpenProgresses` выставляет `TargetLevelId`, страница открывает нужный уровень.

## Границы (YAGNI)

- Экспорт/импорт (`ProgressPackage`) эти строки **не** охватывает — только локально в БД.
- Импорт из сейва их не заполняет — данные чисто ручные (кроме производного столбца 4).
- Строгой валидации столбцов 1–3 нет (свободный текст).
- Видео-прикрепления, сортировка/фильтр строк — вне объёма.
- Разметка и внешний вид юнит-тестами не покрываются (тестовый проект не ссылается на App).
