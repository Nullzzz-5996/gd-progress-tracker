# GD Progress Tracker

Настольное приложение для Windows, которое ведёт учёт прогресса в Geometry Dash:
читает сейв-файл игры, хранит историю попыток по каждому уровню и строит графики
набранных звёзд и демонов. Всё остаётся на твоём компьютере.

![Вкладка «Уровни»](docs/assets/levels.png)

Сайт проекта: <https://nullzzz-5996.github.io/gd-progress-tracker/>

## Возможности

- **Уровни** — список уровней с прогрессом, сложностью и числом попыток.
- **Прогрессы** — журнал попыток: когда и до какого процента дошёл.
- **Статистика** — графики звёзд, демонов и прочих счётчиков аккаунта.
- **Поиск онлайн** — поиск уровней на серверах Geometry Dash.
- **Демонлист** — топ-200 экстрим демонов и топ пройденных уровней: та же вкладка,
  что на сайте, и те же данные — приложение и сайт читают один сервер. Список
  виден без аккаунта.
- **CPS-тест** — измерение скорости кликов.
- **Импорт и обмен** — импорт прогресса из игры, экспорт и импорт файла обмена.
- **Аккаунт (необязательный)** — ник, роль в сообществе и синхронизация прогресса
  между компьютерами через свой сервер. Без входа приложение работает как раньше:
  полностью локально.

## Установка

Скачай `GdTrackerSetup-<версия>.exe` со страницы
[Releases](https://github.com/Nullzzz-5996/gd-progress-tracker/releases/latest) и запусти.

По умолчанию приложение ставится для текущего пользователя — права администратора
и UAC не нужны; в диалоге установки можно переключиться на установку для всех
пользователей. Удаляется штатно, через «Параметры → Приложения».

Требования: Windows 10/11, x64. Отдельно ставить .NET не нужно — рантайм входит
в поставку.

## Данные и приватность

- База: `%LOCALAPPDATA%\GdTracker\gdtracker.db` — обычный файл SQLite, его можно
  скопировать или открыть чем угодно. Удаление приложения его не трогает.
- Сейв игры (`%LOCALAPPDATA%\GeometryDash\CCGameManager.dat`) открывается только
  на чтение — приложение в него не пишет.
- Регистрации и телеметрии нет. Аккаунт — дело добровольное: пока ты не вошёл на
  вкладке «Аккаунт», приложение не отправляет наружу ничего, а единственный сетевой
  запрос — поиск уровней на `boomlings.com`, и только когда ты сам его запускаешь.
- Если аккаунт заведён, в облако уезжает только пакет прогресса (уровни и попытки) —
  тот же, что получается при экспорте в файл. Сервер — твой собственный (см.
  «Сервер синхронизации»), общего публичного сервера у проекта нет.
- Токен входа лежит в `%LOCALAPPDATA%\GdTracker\cloud.token`, зашифрованный DPAPI
  на твою учётную запись Windows; настройки синхронизации — в `cloud.json` рядом.
  Выход из аккаунта и удаление аккаунта локальную базу не трогают.

## Сервер синхронизации

Синхронизация работает через сервер из этого же репозитория — `GdTracker.Api`.
Он хранит по одному снимку прогресса на аккаунт и ничего больше.

Пока сервер не запущен, регистрация и вход на вкладке «Аккаунт» не пройдут —
приложению просто некуда обратиться. Запуск одной командой:

```powershell
powershell -ExecutionPolicy Bypass -File tools/run-sync-server.ps1
```

Скрипт поднимает сервер на `http://localhost:5080` — ровно тот адрес, который
приложение предлагает по умолчанию. Проверить, что сервер отвечает, можно кнопкой
«Проверить сервер» на вкладке «Аккаунт». Пока окно со скриптом открыто, сервер жив.

То же самое вручную:

```powershell
# Ключ подписи токенов: задай свой, иначе сервер сгенерирует его в App_Data
$env:Auth__SigningKey = "длинная-случайная-строка"
dotnet run --project src/GdTracker.Api --no-launch-profile --urls http://localhost:5080
```

Пароль и токен ходят в заголовках, поэтому открытый HTTP годится только для
локальных экспериментов: сервер, доступный из интернета, обязан быть за HTTPS.

### Развёртывание

Сайт проекта — GitHub Pages, он раздаёт только статику и запустить API не может,
поэтому сервер синхронизации живёт отдельно. В репозитории готовы
[Dockerfile](src/GdTracker.Api/Dockerfile) и блюпринт [render.yaml](render.yaml):

```powershell
# Локальная проверка образа
docker build -f src/GdTracker.Api/Dockerfile -t gdtracker-api .
docker run -p 8080:8080 -v gdtracker-data:/data gdtracker-api
```

На Render: New → Blueprint → этот репозиторий; `render.yaml` создаст веб-сервис
с диском для базы и сам сгенерирует ключ подписи токенов. Подойдёт любой хостинг,
умеющий Docker, — образ слушает порт из переменной `PORT` (иначе 8080) и хранит
базу с ключом в каталоге `/data`, который должен быть на постоянном диске.

Когда боевой адрес появится, его достаточно прописать в одном месте —
константе `DefaultServerUrl` в
[CloudSettingsStore.cs](src/GdTracker.Cloud/CloudSettingsStore.cs): она подставится
всем, кто не вводил адрес руками. Ввести свой адрес можно и на вкладке «Аккаунт».

База сервера и ключ подписи лежат в `src/GdTracker.Api/App_Data` (каталог можно
переопределить настройкой `Data__Directory`, строку подключения —
`ConnectionStrings__Db`). Пароли хранятся хешами PBKDF2-SHA256 с солью, вход и
регистрация ограничены по частоте запросов.

## Демонлист

Демонлист есть и на сайте — вкладка [«Демонлист»](https://nullzzz-5996.github.io/gd-progress-tracker/demonlist.html),
и в приложении — вкладка «Демонлист» рядом с «Поиском онлайн». Списки в обоих
местах одни и те же: и страница, и приложение ходят в одни эндпоинты одного
сервера, поэтому перестановка, мнение и заявка сразу видны везде. Списка два:

- **Топ-200 экстрим демонов.** Расстановку меняют только аккаунты с правами
  модератора. Остальные участники высказываются о месте: одно мнение на демона,
  по желанию — с предложением другой позиции. Читать список можно без аккаунта.
- **Топ пройденных уровней.** Участник подаёт заявку со ссылкой на видео, где
  виден или слышен индикатор кликов; без видео и без отметки о кликах заявка не
  принимается. Место в топе проставляет модератор, когда посмотрит запись.

Стартовая расстановка взята из глобального демонлиста (pointercrate.com) и лежит
в двух местах: [demonlist-seed.json](src/GdTracker.Api/Data/Seed/demonlist-seed.json),
которым сервер наполняет пустую базу, и блок `SEED` внутри самой страницы —
из него список читается, пока сервер не подключён. Внутри страницы, а не отдельным
файлом, потому что открытую с диска страницу браузер не пускает за соседними
файлами, и список остался бы пустым.

Сервер накатывает сид только на пустой список — работу модераторов он не
перезаписывает. Оба места обновляются одной командой: `node tools/fetch-demonlist.mjs`.

В приложении вкладка берёт адрес сервера оттуда же, откуда его берёт
синхронизация, — из настроек на вкладке «Аккаунт», и настраивать её отдельно не
нужно. Список читается без входа; чтобы высказаться о месте или подать заявку,
нужно войти. Когда сервер не отвечает, вкладка показывает последнюю прочитанную
расстановку из локальной копии (`demonlist.json` рядом с настройками облака) и пишет,
что она только для чтения.

Списки живут на том же сервере, что и синхронизация. Чтобы заработала страница
сайта:

1. Подними `GdTracker.Api` (см. «Сервер синхронизации») и разреши сайту к нему
   обращаться — источник задаётся настройкой `Cors__Origins__0`. По умолчанию
   разрешены сайт проекта на GitHub Pages и localhost.
2. Пропиши адрес сервера в константе `API_BASE` в начале скрипта
   [docs/demonlist.html](docs/demonlist.html). Пока она пустая, страница
   показывает стартовую расстановку, вшитую в саму страницу, только на чтение
   и честно пишет, что вход и заявки недоступны. Исключение — локальная отладка:
   страница, открытая с `localhost` (например, через Live Server на
   `http://localhost:5500`), сама берёт сервер по `http://localhost:5080` и
   работает целиком, не трогая эту строку. С `file://` так не выйдет: сервер
   не пропустит запрос с такого источника.

Места в топ-200 меняет любой аккаунт от модератора и выше — владелец в том
числе. В строке списка у него появляются стрелки «↑» и «↓»: одно нажатие
переставляет демона на место вверх или вниз, соседи сдвигаются навстречу. Когда
двигать надо далеко, в раскрытой строке остаётся поле «Новое место» — оно ставит
демона сразу на нужную позицию.

Права выдаются не регистрацией, а настройками сервера:

```powershell
$env:Community__Owners__0         = "owner@example.com"
$env:Community__Administrators__0 = "admin@example.com"
$env:Community__Moderators__0     = "mod@example.com"
```

Чтобы не задавать их каждый раз, положи те же настройки рядом с сервером в
`src/GdTracker.Api/appsettings.Local.json` — сервер читает его, если файл есть, а
`.gitignore` держит его вне репозитория, чтобы почта не уехала в публичную
историю. Файл идёт сразу за остальными `appsettings`, поэтому переменные
окружения его перекрывают, а не наоборот:

```json
{ "Community": { "Owners": [ "owner@example.com" ] } }
```

На Render того же добиваются переменной `Community__Owners__0`: в
[render.yaml](render.yaml) она объявлена без значения (`sync: false`), и адрес
вводится в панели.

Ролей четыре. Участник пишет мнения и подаёт заявки. Модератор правит топ-200 и
рассматривает заявки с видео. Администратор — то же плюс выдача прав. Владелец —
старшая роль: правит оба списка наравне с модератором, а сверх того банит
аккаунты. Банов два, оба обратимы и ничего не стирают:

* **полный** (`PUT /api/community/users/{id}/ban`) — ни входа, ни синхронизации:
  забаненный видит причину при попытке войти, а уже выданный ему токен
  отклоняется каждым запросом;
* **в демонлисте** (`PUT /api/community/users/{id}/list-ban`) — вход и облако
  остаются, участие в списке нет: ни мнений, ни заявок, а прежние записи
  пропадают из публичного топа и из мнений и возвращаются, когда бан снимут.

Снимает бан тот же запрос с `banned: false`. Владелец не банит себя и равных
себе, а свою роль не выдаёт: `Community__Owners__*` — единственный её источник,
иначе право банить расходилось бы по сообществу само собой. Список аккаунтов с
поиском по нику и почте отдаёт `GET /api/community/users`; и на сайте, и в
приложении он лежит на вкладке «Участники», которая видна только владельцу.

У каждого аккаунта есть ник — от 3 до 20 символов: буквы (в том числе кириллица),
цифры, дефис и подчёркивание. Ник уникален (регистр не считается), задаётся при
регистрации и меняется потом — на вкладке «Аккаунт» или запросом
`PUT /api/account/username`. Им же и входят: `POST /api/auth/login` принимает
и ник, и почту, так что помнить адрес ради входа не нужно — почта обязательна
только при регистрации. Поле запроса по-прежнему называется `email`, иначе
выпущенные версии приложения остались бы без входа. Под ним аккаунт виден везде: в мнениях о размещении,
в очереди заявок и в топе пройденных. Рядом с ником всюду показывается роль —
значком на сайте и подписью на вкладке «Аккаунт»; у модератора, администратора
и владельца он подсвечен. Аккаунтам, заведённым до появления ников, сервер выдаёт их при
первом запуске: берёт прежнее имя, а если его не было — часть почты до собачки.

Роль поднимается при старте сервера и при регистрации, так что адрес можно внести
и до того, как человек заведёт аккаунт. Дальше администратор выдаёт права через
`PUT /api/community/roles`, не трогая конфигурацию. Настройка роль только
повышает — снять права она не может, для этого есть тот же эндпоинт.

## Сборка из исходников

Нужен [.NET SDK 10](https://dotnet.microsoft.com/download).

```powershell
dotnet build GdTracker.slnx
dotnet test  GdTracker.slnx
dotnet run --project src/GdTracker.App
```

### Инсталлятор

Нужен [Inno Setup 6](https://jrsoftware.org/isinfo.php):
`winget install --id JRSoftware.InnoSetup -e`.

```powershell
powershell -ExecutionPolicy Bypass -File installer/build.ps1
```

Скрипт публикует приложение как self-contained win-x64, компилирует
[installer/GdTracker.iss](installer/GdTracker.iss) и кладёт результат в
`installer/output/GdTrackerSetup-<версия>.exe`. Версия берётся из
[Directory.Build.props](Directory.Build.props) — единственного места, где она задана.

## Структура решения

| Проект | Назначение |
| --- | --- |
| `GdTracker.App` | Приложение на WPF (WPF-UI, LiveCharts) |
| `GdTracker.ViewModels` | Модели представления |
| `GdTracker.Core` | Модели предметной области и расчёты |
| `GdTracker.Data` | Хранилище на SQLite |
| `GdTracker.GameSync` | Чтение сейв-файла и поиск уровней онлайн |
| `GdTracker.Sharing` | Экспорт и импорт прогресса, контракты облачного API |
| `GdTracker.Cloud` | Клиент облака: вход, хранение токена, синхронизация |
| `GdTracker.Api` | Сервер синхронизации (ASP.NET Core + SQLite) |
| `GdTracker.Tests` | Тесты |
